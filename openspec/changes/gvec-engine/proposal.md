## Why

Existing SQLite extensions solve vector search (`sqlite-vec`) and graph queries (`sqlite-graph`) separately, both in pure C. There is no single Rust-native engine that combines graph modeling, vector retrieval, and a unified query language on top of a SQLite-backed storage core. We need a safe, embeddable, and composable option for applications that want graph + vector semantics in one database. The engine MUST be a from-scratch Rust reimplementation, without depending on or copying `sqlite-vec` / `sqlite-graph` code.

## What Changes

- Create a new Rust library + `sqlite3` extension (`libgvec`) that loads into SQLite as a standard loadable extension.
- Introduce a `gvec0` virtual table storing nodes with native graph identity and vector columns.
- Introduce a graph query function `gvec_query()` supporting a Cypher-like graph query language (node/edge matching, patterns, filters, RETURN).
- Combine vector KNN search with graph traversal so queries can start from a semantic (vector) anchor and walk the graph, and node embeddings can be indexed/queried via the `gvec0` vector index.
- Where useful, depend on third-party crates (e.g. distance kernels, ANN indexes, parsers, graph algorithms) instead of reimplementing every primitive.
- Ship Rust bindings (via `rusqlite`) and a Python binding for drop-in use.
- Keep the engine 100% Rust — the loadable-extension entry point and vtab/function registration are generated by the `sqlite-loadable` crate, so no C or raw FFI is written by hand.

## Capabilities

### New Capabilities

- `gvec-core`: core storage engine — nodes, edges, labels, properties, node identity, on a SQLite-backed shadow-table schema with ACID transactions.
- `graph-query-language`: a Cypher-like query-language parser, planner, and executor (`CREATE`, `MATCH`, `WHERE`, `RETURN`, relationship patterns) exposed as `gvec_query()`.
- `vector-retrieval`: vector (float/int8/binary) storage in `gvec0` virtual tables plus KNN search and an approximate index, implemented directly in Rust.
- `graph-vector-integration`: combining vector similarity results with graph traversal (vector-anchored graph queries, vector predicates on nodes).
- `sqlite-extension`: the `sqlite3` loadable extension entry point and virtual-table/function registration, generated via `sqlite-loadable` (no hand-written C ABI shim).
- `language-bindings`: Rust crate (rusqlite-based) and Python bindings for loading the extension and running queries.

### Modified Capabilities

- (none — no existing specs in this repo)

## Impact

- New Rust crate layout: storage module, cypher parser/planner/executor, vector index, `extension` crate (sqlite-loadable generated), bindings.
- Dependencies: `rusqlite`, `serde_json` (properties), `sqlite-loadable` (extension entry point + vtab/functions); optional crates.io libraries for distance kernels (e.g. `simsimd`), ANN indexes, and graph algorithms. No dependency on `sqlite-vec` or `sqlite-graph` source or binaries.
- New SQL surface: `CREATE VIRTUAL TABLE ... USING gvec0(...)`, `SELECT gvec_query(...)`.
- This is a new, standalone project; `sqlite-vec` and `sqlite-graph` are referenced only as behavioral/design inspiration, never as dependencies.
